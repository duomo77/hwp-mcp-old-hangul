# 옛한글 파일 수정 검증

검증일: 2026-10-15  
대상: `hwp-mcp-old-hangul` `0.3.0-old-hangul.2`, `@rhwp/core 0.7.7`

## 판단

합성 HWPX의 옛한글 텍스트 생성·추가·치환·문단 수정·표 셀 수정은 저장 후 재열기 검증을 통과했습니다.
HWP 5.x 읽기 지원과 HWP 쓰기 지원은 다릅니다. **이 버전에서 `.hwp` 수정·저장은 미지원**이며,
실제 한컴오피스에서의 글꼴 표시·쪽 배치까지 검증한 결과는 아닙니다.

## 발견한 문제와 수정

기존 98개 테스트는 통과했지만, 수정 전 새 검증 14개 중 10개가 실패했습니다.
최종적으로 수정 통합 테스트 15개와 XML 검색·보존 테스트 10개를 추가했습니다.

| 재현한 문제 | 보완 |
|---|---|
| 한 텍스트 노드에 같은 옛글자가 두 번 있어도 마지막 한 번만 치환 | 겹치지 않는 모든 일치 위치를 치환하고 실제 횟수 집계 |
| `&#xF53A;` 같은 숫자 참조와 `&amp;` 같은 이름 참조를 검색하지 못함 | 검색용 문자열에서 참조를 한 번 해석하고 원본 위치에만 패치. 비일치 참조 표기는 유지 |
| 읽기 결과는 자모인데 파일에는 PUA여서 검색 실패 | `replace_hwp_text` / `fill_hwp_template`에 `old_hangul: "unicode"` 선택 인자 추가. 기본은 `preserve` |
| 한 음절의 자모가 여러 run에 분리되면 검색 실패 | 같은 문단의 인접한 텍스트 run을 검색 시 연결. run 태그와 서식 참조는 유지 |
| 문단 설정 시 쪽 설정이 삭제되고 중첩 표가 있으면 XML 구조 손상 | 문단을 중첩 깊이로 식별하고 자체 텍스트만 수정. 쪽 설정과 중첩 표 보존 |
| 여러 run이 있는 표 셀 수정 시 뒤의 원문이 남음 | 첫 문단에 입력하고 나머지 자체 텍스트를 비움. 셀·문단 구조 유지 |
| 빈 검색어·잘못된 모드가 저장을 진행 | 입력 검사 추가. 문자열이 아닌 값과 XML 불가 문자도 저장 전에 거부 |
| 구조 편집 도구가 `.hwp` 이름으로 HWPX ZIP을 저장할 수 있음 | 출력 확장자 `.hwpx` 검사 추가 |

## 검증 범위

| 항목 | 결과 |
|---|---|
| 옛한글 PUA·유니코드 자모가 섞인 HWPX 생성·문단 추가 | 통과: 저장 후 WASM 파서로 다시 읽어 문자열 비교 |
| 아래아·확장 자모·방점·채움문자·미지원 PUA·이모지 보존 | 통과: 코드포인트를 포함한 정확한 문자열 비교 |
| 같은 노드의 반복 치환·분리 run·숫자 참조 | 통과 |
| PUA와 유니코드의 동등 검색·템플릿 채우기 | 통과: 선택한 경우에만 동등 비교, 다른 문자 인코딩은 유지 |
| PUA 확장 결과의 일부 자모만 검색 | 통과: 부분 치환하지 않고 0건 반환 |
| 문단·컨트롤 경계, 속성·주석·CDATA 등 비대상 보존 | 통과 |
| 문단 설정의 쪽 설정·중첩 표 보존 | 통과: XML 원문 비교 및 재열기 |
| 여러 run 표 셀의 잔여 텍스트 제거 | 통과: 재열기 후 표 내용 비교 |
| 원본 보존·비대상 ZIP 항목 보존 | 통과: 별도 출력 경로에서 원본 전체 바이트와 비대상 항목의 압축 해제 바이트 비교 |
| MCP 서버를 통한 치환 → 파일 저장 → 읽기 호출 | 통과: 실제 SDK Client/Server 인메모리 전송으로 검증 |
| `.hwp` 저장·잘못된 출력 확장자 | 통과: 거부하고 출력 파일을 생성하지 않음 |
| 실제 사용자가 보유한 옛한글 문서·한컴오피스 화면 | 미검증: 해당 문서와 네이티브 한컴 실행 환경이 제공되지 않음 |

재현:

```bash
npm ci
npm run build
npm test
```

결과: **24개 테스트 파일, 123개 테스트 통과**. 주요 추가 테스트:
`test/tools.old-hangul-edit.test.ts`, `test/core.hwpx-text.test.ts`.

추가로 컴파일된 `dist` 코드로 혼합 인코딩·중첩 표가 있는 입력 1개와 수정본 4개를 생성했습니다.
Python 표준 `zipfile`로 5개 ZIP의 CRC를 검사하고 `xml.etree.ElementTree`로 내부 XML/HPF
총 35개를 별도로 파싱했습니다. 모두 성공했으며 각 파일의 쪽 설정 1개·표 1개·셀 2개가 유지됐습니다.
이는 독립 XML 파서의 구조 검사이며 한컴오피스의 완전한 OWPML 스키마 검증은 아닙니다.

## 사용 시 해석

- `old_hangul: "unicode"`는 검색을 위한 비교 방식입니다. 파일 전체를 유니코드로 바꾸거나 원래 글꼴을 교체하지 않습니다.
- 새 문자열은 입력한 그대로 저장합니다. 구형 PUA 전용 글꼴에서 유니코드 자모가 제대로 표시되는지는 별도 확인해야 합니다.
- 인접 run을 가로지른 새 문자열은 첫 일치 run의 서식을 따릅니다. 문자별 기존 서식을 새 문자열에 재배분하지 않습니다.
- 기존 도구 전체의 레이아웃·필드·이미지·행열 삽입·셀 병합을 옛한글 문서에서 검증했다고 해석하면 안 됩니다.
- 표 셀 전체 수정은 중첩 표를 지원하지 않습니다. 복잡한 구조는 `replace_hwp_text`로 필요한 문자열만 바꾸는 방식이 검증 범위에 더 가깝습니다.
- 문단·셀 전체 수정 시 `<hp:t>` 안의 인라인 XML 컨트롤은 거부합니다. 일반 문자열 치환을 사용하세요.
- 특수 글꼴, 실제 한컴오피스 화면, 인쇄 결과까지 보장하려면 실제 문서를 복사본으로 열어 추가 검증해야 합니다.
